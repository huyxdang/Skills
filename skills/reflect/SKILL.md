# Reflect

Use the active conversation and produced artifacts. If more history is needed, use supported chat tools within the named scope; do not search unrelated transcript stores.

Review judgment, tooling, and alternative approaches. For a substantial task, use `../swarm/SKILL.md` for independent read-only reviews, then verify their evidence. Distinguish accepted lessons, rejected overgeneralizations, and structural fixes better handled by types, checks, or tools.

Inspect each proposed destination. Prefer a narrow correction to an existing skill over a new universal rule. Use skill-creator for substantive edits. Never modify installed plugin caches. If the user asked to update the skill, apply those authorized edits and validate them. If they asked only for reflection or proposals, present concrete edits for review.

Keep external backlog suggestions in the report unless the user requested filing them. Report actual edits, evidence, validation, and unresolved choices without pretending proposals have been applied.

## Codex execution

Resolve bundled paths from this skill directory. Read a named sibling skill before using its workflow; if it is not installed, report that dependency and use only capabilities actually available. Host instructions and the user’s scope govern all actions. A skill does not authorize unrelated edits, external messages, merges, or publication.
