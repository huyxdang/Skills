# Writing contract

- Lead with what changed for the user.
- Use one thought per sentence.
- Prefer concrete nouns and active verbs.
- Keep headings and lists only when they improve scanning.
- State uncertainty and missing verification directly.
- Explain the maintainer impact after the user impact.
- Keep code comments for non-obvious reasons. Do not narrate nearby code.
- Link only artifacts inspected or produced in the current work.
- Include tradeoffs and open decisions when they affect the handoff.
